# Реестр средств разработки и приёмки

Эти инструменты нужны для сборки и испытаний. Пользователю сервера требуется
только бинарник своей ОС/архитектуры и API-ключ.

- `install-sdk.sh DIRECTORY [CACHE]` — официальный SDK11.0.100 Linux-x64 с
  проверкой закреплённого SHA-512, без изменения глобальной установки.
- `run-dev.sh` — локальный сервис на loopback18080, случайный приватный ключ,
  отдельные spool и журналы; ключ не печатается и исключён из Git.
- `run-harness.sh [--include-shutdown]` — C# HTTP-проверки локального стенда.
- `stop-dev.sh` — штатный REST-drain собственного локального стенда.
- `close-dev-fixture-inputs.py` — закрывает stdin только собственных fixture
  из этого репозитория, оставшихся после неуспешного испытания.
- `inspect.sh` — закреплённый JetBrains InspectCode с приватным SDK11;
  результат SARIF в `.artifacts/inspectcode.sarif`.
- `create-linux-vm.sh` — новая Ubuntu26.04 ВМ с закреплённым образом; коллизии
  имён и файлов отклоняются. Не меняет существующие машины.
- `bootstrap-linux-vm.sh` — копирует один бинарник и приватное окружение,
  проверяет отсутствие dotnet, запускает свой сервер через systemd.
- `tunnel-linux-vm.sh` — SSH-туннель к loopback API лабораторной ВМ.
- `vm-build-through-api.py` — установка пакетов/SDK и сборка проекта отдельными
  REST-командами, с сохранением ID, exitCode и обоих потоков в квитанциях.
- `verify-lifecycle.py` — изолированные проверки настоящего PTY Ctrl-C,
  отказа без ключа, exclusive-spool и ротации журналов. Поддерживает приёмку
  self-contained бинарника; подробности в `docs/lifecycle-evidence.md`.
