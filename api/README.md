# Контракт API

`openapi.json` — первичный контракт версии `/v1`. Серверный абстрактный контроллер
и DTO в `src/ExecServer/Contracts/Api.g.cs` генерируются закреплённым NSwag 14.8.0:

```sh
dotnet run --project tools/ContractGenerator -- api/openapi.json src/ExecServer/Contracts/Api.g.cs
dotnet run --project tools/ContractGenerator -- api/openapi.json src/ExecServer/Contracts/Api.g.cs --check
```

Генератор нужен только разработчику. Поставка сервиса не требует NSwag, Python,
Node или установленного .NET runtime. У генератора есть `packages.lock.json`.
Он создаёт серверный контракт с `System.Text.Json`; Newtonsoft используется
лишь транзитивно самим NSwag при генерации и не требуется приложению.

Обязательность и типы полей заданы схемой. Дополнительные поля структурированных
запросов запрещены. Проверка взаимоисключающих `text`/`binary` остаётся обязанностью
обработчика: C# DTO не может выразить `oneOf`. Генератор удаляет это ограничение
только из своей проекции схемы, чтобы NSwag сохранил оба поля, а исходная OpenAPI
и обязательная проверка запроса сохраняют ограничение. `binary` в C# — `byte[]`,
а в JSON — обычная base64-строка.

Каждый маршрут требует Bearer API key, включая статус и запрос остановки.
Защищённый `GET /v1/openapi.json` возвращает встроенную копию исходного документа.
Этот маршрут обслуживает сам host; он исключается только из генерации
абстрактного контроллера, чтобы не создавать второй обработчик того же URL.
Ключ даёт право запускать программы с полномочиями учётной записи сервиса:
это механизм аутентификации, а не отдельная песочница или ограничитель команд.

Позиции и лимиты считаются в исходных байтах. `limit` применяется отдельно к
stdout и stderr и ограничивается серверной настройкой размера порции. Формат
чтения выбирает клиент; по умолчанию UTF-8. Неверный UTF-8, в том числе срез внутри
символа, даёт ошибку с длиной накопленных исходных данных и не потребляет вывод.
Клиент может повторить чтение в бинарной форме; формат не угадывается.

`blobId` адресует отдельный исходный поток. Ссылка сама не считается чтением;
`returnedBytes=0` и `nextOffset` не продвигается. Бинарный endpoint возвращает
сырые байты и позиции в заголовках `X-Output-*`. Для `durable=false` успешная
передача окончательного хвоста каждого потока после финализации захвата позволяет
удалить весь запуск. Пустой завершённый поток не требует отдельного чтения.
При `durable=true` удаление только явное и всегда вместе с метаданными.

Окружение и cwd по умолчанию наследуются от сервиса, переданное окружение
переопределяет отдельные значения. stdin остаётся открыт до явного `close` или
`close-stdin`, если `closeStdin` не был установлен при запуске. HTTP-таймаут
ожидания не останавливает программу. Перезапуск сервиса не восстанавливает jobs.
