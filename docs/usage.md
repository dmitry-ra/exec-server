# Запуск и использование

Для целевой ОС берётся соответствующий self-contained бинарник: Linux/macOS
`exec-server`, Windows `exec-server.exe`. Устанавливать .NET на целевой машине
для запуска сервиса не требуется. Различные ОС/архитектуры имеют разные файлы.
Обычные системные библиотеки ОС и запускаемые вами программы остаются внешними.

На Unix:

```sh
chmod +x exec-server
EXECSERVER_API_KEY='ваш-случайный-api-ключ' ./exec-server
```

По умолчанию слушается `http://127.0.0.1:5080`. Адрес меняется через `--urls`.
Все HTTP-маршруты требуют `Authorization: Bearer <ключ>`, включая status и OpenAPI.
Без установленного ключа сервер отказывается запускаться. Для удалённого доступа
можно использовать SSH-туннель или собственный TLS reverse proxy; встроенной
настройки внешней инфраструктуры нет. Ключ даёт право выполнять программы с
правами пользователя сервиса: это не песочница и не система ограниченных команд.

OpenAPI: `GET /v1/openapi.json`. Статус сервиса: `GET /v1/status`.

Пример запроса запуска на Linux:

```json
{
  "executable": "/bin/ls",
  "args": ["-la", "/tmp"],
  "durable": true,
  "closeStdin": true,
  "waitMilliseconds": 1000
}
```

Отправляется `POST /v1/executions`. Ответ содержит наш `id`, настоящий `pid`,
состояние, длительность, счётчики и известный код завершения. `waitMilliseconds:0`
возвращает управление сразу. Разрыв HTTP-соединения не отменяет процесс.

`GET /v1/executions/{id}` возвращает состояние. `GET /v1/executions/{id}/output`
читает stdout и stderr раздельно. Смещения `stdoutOffset`/`stderrOffset` относятся
к сырым байтам, не символам. Без смещения чтение начинается с нуля. `limit`
ограничивает порцию, `remainingBytes` и `nextOffset` показывают продолжение.
Большая порция возвращает `blobId`; `GET /v1/blobs/{blobId}` читает сырые байты.

Текст UTF-8 — формат по умолчанию. `format=base64` возвращает бинарные данные
в поле `binary`. Неполная/неверная UTF-8-последовательность даёт явную ошибку,
не заменяется другим символом и не удаляет вывод; можно повторить чтение
как base64. Для long polling задаётся `waitMilliseconds`: новые данные будят запрос.

`POST /v1/executions/{id}/stdin` принимает `{ "text":"..." }` либо
`{ "binary":"BASE64" }`. Эти формы взаимоисключающие. `{ "close":true }`
или `POST /v1/executions/{id}/close-stdin` закрывает pipe; это не отправка Ctrl-D.
Shell запускается как обычная программа с аргументами, не создаётся автоматически.
Первая версия использует pipes: терминала, TUI и интерактивного sudo через TTY
пока нет. Явный `sudo -S` применим, если политика sudo разрешает stdin.

Без durable после выхода программы и чтения окончательных хвостов обоих потоков
удаляются метаданные и весь вывод. Чтение хвоста означает отказ от предыдущих
байтов. Надёжного подтверждения доставки от клиента в этом режиме нет.
С `durable:true` сохраняются обе сущности до `DELETE /v1/executions/{id}`.
Работающий процесс удалять нельзя. Durable не означает сохранение после
перезапуска: каталог временного вывода очищается при новом запуске сервиса.

`POST /v1/signals` с `{ "pid":1234,"signal":15 }` отправляет Unix-сигнал.
На Windows этот вызов явно отклоняется. PID адресуется в терминах целевой ОС.
`GET /v1/executions/{id}/processes` — диагностический снимок PID/PPID/имени,
без гарантии атомарности и истории.

`POST /v1/shutdown`, Ctrl-C и штатный Unix SIGTERM переводят сервис в draining:
новые запуски запрещены, I/O существующих программ работает; сервис ждёт
непосредственно запущенные процессы. Автоматического убийства дерева нет.
SIGKILL и авария не гарантируют завершение потомков. Дочерняя программа сама
определяет поведение своих потомков и унаследованных pipe.

Настройки окружения: `ExecServer__MemoryThresholdBytes`, `MaxReadBytes`,
`InlineBytes`, `DefaultWaitMilliseconds`, `MaxWaitMilliseconds`, `SpoolDirectory`,
`LogDirectory`, `LogFileBytes`, `LogFileCount` — последние имена также требуют
префикса `ExecServer__`. Журналы — ротируемые JSON; параметры операций пишутся,
тела stdin/stdout/stderr и заголовок авторизации не пишутся. Учетные данные
в аргументах и явно переданном окружении пользователь должен считать видимыми
в диагностике согласно текущему контракту.
